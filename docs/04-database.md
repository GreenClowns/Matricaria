# 04. База данных (черновик)

Один мир хранится в одном файле SQLite: `saves/<мир>/world.db`.
Код — пакет `core/matricaria/world` (версия 0.3). Точная схема — в `core/matricaria/world/schema.py`.

## Главные правила ядра

- **Мир меняется только через методы `World`.** Каждый метод проверяет действие кодом, меняет таблицы и записывает событие в журнал **одной транзакцией** («всё или ничего»). Если проверка не прошла, не меняется ничего и в журнал ничего не пишется.
- **Журнал только дополняется.** Это защищено самой базой (триггеры SQLite): даже ошибка в коде не изменит и не удалит запись.
- **Время мира** — целое число игровых минут от начала. На экран выводится как `Day 3, 14:20`.
- **Версия схемы** хранится в самой базе (`PRAGMA user_version`). Когда добавятся новые таблицы, старые сохранения обновятся миграцией.
- Текст ошибок видит игрок, поэтому он по-английски (D40).

## Таблицы

Сделано в 0.3:

| Таблица | Что хранит | Ключевые поля |
|---|---|---|
| `world` | Параметры мира (одна строка) | name, setting (`fantasy` / `modern`), seed, time, rule_mode (`strict` / `narrative` / `free`), scenario_type (`standard` / `cozy`), travel (`map` / `scenes`) |
| `location` | Места и здания | id, name, kind, parent_id, x, y, discovered_at и discovered_by (если место открыто по ходу игры) |
| `character` | Герои и NPC | id, name, role, profession, personality (JSON), controller (`player` / `ai`), location_id, sprite, portrait, **cash** (наличные), **bank** (на счёте) |
| `stats` | Характеристики и состояние | character_id, strength, agility, endurance, intellect, charisma (1–10), max_health, health, alive, conditions (JSON-список) |
| `relation` | Отношения from → to | liking, trust, fear, respect (−100…100), love (0…100), knows_name |
| `ability` | Способности | character_id, kind (`divine_will`, `immortality`, `omniscience`, `magic:<школа>`…), params (JSON) |
| `item` | Предметы | id, kind, name, owner_id **или** location_id, base_price, equipped (`held` / `worn`), damage_min, damage_max |
| `fact` | Факты о мире | subject, predicate, object, status, canon, since, until, source, replaced_by |
| `knowledge` | Кто какой факт знает | character_id, fact_id, believes, source, learned_at |
| `event` | Журнал событий (**только дополняется**) | id, time, kind, actor_id, participants (JSON), data (JSON), dice (JSON), basis (`rules` / `ability` / `author`) |
| `snapshot` | Снимки для отката | id, time, last_event_id, label, file |

Появятся в своих версиях:

| Таблица | Что хранит | Версия |
|---|---|---|
| `need`, `goal`, `schedule` | Потребности, цели, распорядок NPC | 0.4 |
| `message`, `pending` | Сообщения диалогов, очередь «На утверждение» | 0.5 |
| `summary`, `lore_entry` | Сводки, лорбук | 0.6 |
| `market`, `faction`, `asset` | Цены в регионе, фракции, картинки | когда понадобятся |

## Деньги (D41)

У каждого персонажа два числа в самой мелкой монете (медяк, цент):
- **cash** — наличные, отдаются только из рук в руки, когда оба в одном месте;
- **bank** — деньги на счёте, переводятся на любое расстояние. В фэнтези это, например, хранилище гильдии.

Деньги никогда не уходят в минус. Как их показать (монеты или карта), решает интерфейс сеттинга (D42).

## Здоровье

Максимум здоровья по умолчанию: **10 + 2 × Выносливость** (от 12 до 30). *Предложено, ждёт согласования автора.*
Здоровье не выходит за пределы 0…максимум. На нуле персонаж умирает, у бессмертного здоровье не опускается ниже 1.
Мёртвого нельзя вылечить, только воскресить. Мёртвый или потерявший сознание персонаж не действует сам.

## Основание события (D22)

| Основание | Когда |
|---|---|
| `rules` | Обычное действие по правилам. Действующий персонаж жив и в сознании |
| `ability` | Чудо: у действующего персонажа есть нужная способность (`divine_will` подходит для любого чуда) |
| `author` | Воля автора, разрешена в любом режиме правил (D44) |

По правилам (`rules`) **нельзя**: создать предмет или деньги из ничего, убить мгновенно, воскресить, дать или забрать способность, изменить характеристику, задать отношения точными числами, передать персонажа игроку или ИИ, перенести чужой предмет, добавить или изменить канон.

## Статусы факта

- `truth`: так есть на самом деле.
- `belief`: так думает NPC (кто именно — в `knowledge`).
- `rumor`: слух.
- `lie`: NPC сознательно говорит неправду.

Правда не может противоречить другой текущей правде: у `spouse_name` одно значение. Если значений несколько (дети, друзья), факт добавляется с пометкой `multiple`. Слух и ложь могут спорить с правдой — так рождаются истории.

**Изменённый факт не стирается.** У старого ставится `until` (когда перестал быть верным) и `replaced_by` (новый факт). NPC, знавший старый факт, помнит его, пока не узнает новость.

Персонаж со способностью `omniscience` знает всю текущую правду мира.

## Пример

```json
{ "subject": "npc_17", "predicate": "spouse_name", "object": "Марта",
  "status": "truth", "canon": false, "since": 17280, "until": null, "source": "dialog_88" }
```

## Откат

Снимок — это копия базы на определённый момент. Откат = восстановить снимок.
Перед откатом ядро само делает снимок «до отката», поэтому ничего не теряется и к нему можно вернуться (D43).

# 13. Уровни железа: игра без API и на слабом компьютере (черновик)

Игра должна запускаться **всегда**: даже без видеокарты, без интернета и без API.
ИИ делает игру богаче, но не обязателен. Менеджер моделей сам определяет уровень по железу,
а пользователь может выбрать другой в настройках.

## Уровни

| Уровень | Железо | Текст (диалоги) | Картинки (портреты) |
|---|---|---|---|
| **0. Без ИИ** | Любой компьютер | Шаблоны реплик из фактов базы | Портреты из слоёв (бумажная кукла) |
| **1. Только процессор** | 8 ГБ ОЗУ, без видеокарты | Маленькая модель на процессоре | Портреты из слоёв |
| **2. Видеокарта 4 ГБ** | 4 ГБ видеопамяти, 16 ГБ ОЗУ | Qwen3-4B (Q4_K_M) | Z-Image Turbo (Q3_K / Q4_0) |
| **3. Видеокарта 8 ГБ+ или API** | 8 ГБ+ или ключ API | Модели побольше | Генерация в высоком разрешении |

Уровни можно смешивать: например, текст через API, а портреты из слоёв.

## Уровень 0: без ИИ

### Портреты из слоёв

Как редактор LPC для спрайтов, только для портрета по плечи.
Портрет собирается из готовых пиксельных слоёв, нарисованных в стиле [12](12-art-and-body.md):

```
фон → задние волосы → тело и шея → одежда → голова → глаза (по эмоции) →
брови и рот (по эмоции) → передние волосы → аксессуары
```

- **Цвет:** слои рисуются в серой палитре, цвет волос, глаз и кожи подставляется заменой палитры (palette swap). Новых картинок для каждого цвета не нужно.
- **Эмоции:** 8 вариантов глаз, бровей и рта ([06](06-ai-formats.md)).
- **Тело ([12](12-art-and-body.md)):** у каждого слоя тела и одежды есть варианты по телосложению и уровням частей тела. Для уровней выше нарисованных слой растягивается без сглаживания.
- **Размер:** гиганты и крошечные персонажи показываются через кадрирование (`framing`), отдельные слои не нужны.
- **Откровенный режим:** слои без одежды не входят в базовый набор. Их можно поставить отдельным пакетом, и он работает только при разрешении из [12](12-art-and-body.md#уровень-содержания).

Откуда взять слои: нарисовать вручную, взять открытые наборы с совместимой лицензией
или **один раз сгенерировать на машине разработчика** (уровень 2–3), обработать `pixelize` и доработать руками.
Результат входит в игру, и игроку модель уже не нужна.

### Реплики без модели

- Каждый NPC отвечает репликами из шаблонов: приветствие, слух, просьба, торговля, прощание.
- В шаблон подставляются факты из базы: имя, отношения, слухи, которые NPC знает.
- Вариант реплики выбирается по характеру (`traits`) и отношению к игроку.
- Игрок выбирает фразу из списка вариантов, свободный ввод недоступен.
- Симуляция ([08](08-simulation.md)) и так работает без ИИ, поэтому мир живёт и на этом уровне.

Шаблоны хранятся в файлах сценария, их можно писать без программирования.

## Уровень 1: только процессор

- llama.cpp на процессоре с маленькой моделью (1–2 млрд параметров, Q4): около 1–2 ГБ ОЗУ. Отвечает медленно, но отвечает.
- Портреты по-прежнему из слоёв: генерация картинок на процессоре занимает минуты.

## Уровень 2: видеокарта 4 ГБ

Обе модели под лицензией **Apache 2.0**, это совместимо с принципом «только открытое» (D3).

| Задача | Модель | Файл | Примерный размер |
|---|---|---|---|
| Текст | Qwen3-4B-Instruct-2507 | `Qwen3-4B-Instruct-2507-Q4_K_M.gguf` | ~2,5 ГБ |
| Картинки | Z-Image Turbo | `z_image_turbo-Q3_K.gguf` или `-Q4_0.gguf` | — |
| Картинки: кодировщик текста | Qwen3-4B-Instruct-2507 | тот же файл, что для текста | — |
| Картинки: VAE | из FLUX.1-schnell | `ae.safetensors` | — |

Z-Image использует Qwen3-4B как кодировщик текста, поэтому **один файл модели скачивается один раз и нужен для обеих задач**.

Запуск stable-diffusion.cpp на 4 ГБ (по инструкции из вики проекта):
```bash
sd --diffusion-model z_image_turbo-Q3_K.gguf --llm Qwen3-4B-Instruct-2507-Q4_K_M.gguf \
   --vae ae.safetensors --offload-to-cpu --diffusion-fa --cfg-scale 1.0 -H 1024 -W 512 \
   -p "<запрос из portrait_prompt>"
```
Точные имена флагов сверить с версией stable-diffusion.cpp, которую ставит менеджер.

### Две модели не помещаются одновременно

4 ГБ хватает либо на текст, либо на картинки. Поэтому:
1. Портреты генерируются **заранее и редко**: при создании персонажа и при заметной смене тела (`portrait_is_stale`). Все 8 эмоций сразу, результат кэшируется в `asset`.
2. Пока идёт генерация, текстовая модель выгружается, а диалог ждёт или использует шаблоны уровня 0.
3. Если генерация не удалась или слишком долгая, ставится портрет из слоёв.

### Откровенный режим

У Qwen3-4B по умолчанию `allows_explicit = false`: обычная instruct-модель часто отказывается от таких сцен.
Пользователь может поставить другую модель и сам отметить, что она это допускает ([12](12-art-and-body.md#уровень-содержания)).

## Что нужно проверить на реальном железе

- [ ] Скорость Qwen3-4B Q4_K_M на 4 ГБ и сколько слоёв уходит на процессор при контексте 8–16 тыс. токенов.
- [ ] Время одного портрета Z-Image Turbo Q3_K на 4 ГБ и качество после `pixelize`.
- [ ] Насколько хорошо Z-Image рисует аниме-стиль. Если плохо, искать дообученную модель или LoRA с открытой лицензией.
- [ ] Хватает ли 1–2B модели на процессоре для связных диалогов на русском.

# 14. Как мы работаем

Инструкция для автора: как вести проект через отдельные чаты Claude Code.

## Короткие пояснения

| Слово | Что значит |
|---|---|
| **Репозиторий** | Папка проекта на GitHub со всей историей изменений |
| **Коммит** | Сохранённый шаг изменений с описанием |
| **Ветка** | Отдельная копия проекта для одной задачи; основная ветка называется `main` |
| **Pull Request (PR)** | Предложение влить ветку в `main`. Его можно посмотреть и обсудить |
| **Merge** | Слияние: изменения из ветки попадают в `main` |

## Главное правило

**Чаты не помнят друг друга.** Всё важное записывается в репозиторий:
- [CLAUDE.md](../CLAUDE.md) — правила, их Claude читает в начале каждой сессии;
- [decisions.md](decisions.md) — что решили;
- [10-roadmap.md](10-roadmap.md) — что сделано и что дальше;
- [CHANGELOG.md](../CHANGELOG.md) — что изменилось в каждой версии.
- [ideas.md](ideas.md) — идеи на будущее. Скажите в любом чате «запиши идею: …», и она не потеряется.

## Один чат — одна задача

| Чат | Задача | Версия |
|---|---|---|
| Планирование | Документы, решения, дорожная карта | 0.1 и между версиями |
| Эксперимент | Надёжность ИИ | 0.2 |
| Ядро | База, факты, журнал, откат | 0.3 |
| Симуляция | Время, NPC, события, слухи | 0.4 |
| ИИ и валидатор | Запросы, ответы, проверка | 0.5 |
| Память | Сводки, лорбук | 0.6 |
| Godot | Мир и диалог | 0.7–0.8 |

Одновременно — **1–2 чата**, не больше: нужно успевать проверять, и чаты не должны менять одни и те же файлы.

## Как начать новый чат

1. Откройте **claude.ai/code** → новая сессия → выберите репозиторий `GreenClowns/Matricaria`.
2. Первое сообщение — по шаблону:

```
Работаем над версией 0.3 «Ядро мира» из docs/10-roadmap.md.
Прочитай CLAUDE.md и документы по теме, затем предложи план работы.
```

3. Claude предложит план. Если всё понятно — скажите «делай».

## Как закончить работу

1. Claude отправляет ветку на GitHub и даёт ссылку на Pull Request.
2. Claude даёт команды для проверки на Fedora — выполните их и напишите, что получилось.
3. Если всё хорошо, на странице PR нажмите **Merge pull request** → **Confirm merge**.
4. Изменения попадают в `main`, и следующий чат их увидит.

## Как проверять на своём компьютере

Один раз скачать проект:
```bash
git clone https://github.com/GreenClowns/Matricaria.git
cd Matricaria
```

Каждый раз перед проверкой — получить свежую версию:
```bash
cd Matricaria
git checkout main
git pull
```

Проверить ветку до слияния (имя ветки даст Claude):
```bash
git fetch
git checkout имя-ветки
```

## Если что-то пошло не так

- Чат запутался — откройте новый: память в репозитории, ничего не потеряется.
- PR не нравится — не нажимайте Merge, напишите в чат, что исправить, или закройте PR.
- Непонятная ошибка в терминале — скопируйте её текст целиком в чат.

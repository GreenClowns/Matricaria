# 09. Карточки и сценарии (черновик)

## Карточка персонажа

Один файл `.png`. Сама картинка — это портрет, а внутри (в чанке PNG `matricaria`) лежит JSON:

```json
{
  "format": "matricaria-character",
  "version": 1,
  "name": "Кира",
  "sprite": { "body": "slim", "skin": "light", "hair": { "style": "long", "color": "#c9ced8" } },
  "portraits": { "style": "anime", "seed": 48213, "emotions": ["neutral", "happy", "angry"] },
  "personality": {
    "traits": { "kind": 60, "social": 20, "honest": 40 },
    "speech": "Коротко, с иронией",
    "goals": ["Найти брата"],
    "fears": ["Огонь"]
  },
  "backstory": "...",
  "example_lines": ["Ну и где тут обещанное приключение?"]
}
```

Поле `version` обязательно: при изменении формата старые карточки конвертируются автоматически.

## Сценарий (мир)

Папка или архив `.matricaria`:
```
manifest.json   — название, сеттинг, seed, версия формата
lore/           — записи лорбука
npcs/           — карточки NPC
events/         — шаблоны событий
map/            — заготовки карты (необязательно)
```

Любой герой может войти в любой сценарий. Сценарий можно отдать другому человеку, и он сыграет в нём своим персонажем.

## Импорт персонажей из SillyTavern, Janitor AI и других сайтов

Игра читает открытый формат **Character Card** (V2 и V3), которым пользуются SillyTavern, Chub и большинство похожих сайтов:
- `.png` с текстом персонажа внутри (чанк `chara` для V2, `ccv3` для V3);
- `.json` с теми же полями.

**Janitor AI.** Насколько известно, своей выгрузки у него нет; персонажей переносят сторонними инструментами в тот же формат `.png` или `.json`, и тогда импорт работает. Если автор персонажа **скрыл описание**, мы это не обходим. Перед реализацией проверить, что сейчас умеет Janitor.

### Что во что превращается

| Поле Character Card | В Matricaria |
|---|---|
| `name`, `description`, `personality` | Имя, характер, речь, цели, страхи |
| `scenario` | Начало истории: сеттинг, место, кем персонажи приходятся друг другу |
| `first_mes`, `alternate_greetings` | Варианты первой сцены |
| `mes_example` | `example_lines` |
| `character_book` | Записи лорбука: ключи, приоритет (`insertion_order`), условия (`secondary_keys`, `selective`), постоянные (`constant`) |
| Картинка карточки | Портрет с эмоцией «спокойствие» |
| `tags` | Подсказка сценария: `romance`, `slice of life`, `fluff` → «Уютная история» |
| `creator`, `character_version`, `creator_notes` | Сохраняются: автор карточки указан всегда |
| `system_prompt`, `post_history_instructions` | Сохраняются как часть характера, но **правил ядра не отменяют** |
| `extensions` и неизвестные поля | Хранятся как есть, чтобы не потерять |

Макросы `{{user}}` и `{{char}}` поддерживаются: при игре на их место подставляются имена.

### Автоматическая настройка

Чего в Character Card нет, игра предлагает сама: пять характеристик, профессию, начальные отношения (из сценария: «подруга детства» → высокие симпатия и доверие), распорядок дня, эмоции портрета.

1. Игрок перетаскивает файл (в 0.6 — команда в терминале).
2. Ядро читает карточку; ИИ **предлагает** недостающие поля.
3. Экран «Проверьте персонажа»: всё можно поправить, затем «Готово». Только после этого персонаж записывается в базу.

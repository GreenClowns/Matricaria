# Журнал решений

Каждое решение фиксируется здесь, чтобы не обсуждать его заново.
Чтобы отменить решение, нужно добавить новую запись, а не стирать старую.

| № | Решение | Почему |
|---|---|---|
| D1 | Название **Matricaria**, логотип: пиксельная ромашка | Латинское имя ромашки; *matrix* означает «источник» |
| D2 | Проект открытый и некоммерческий; код под **GPL-3.0** | Графика LPC требует совместимой лицензии; запретить чужое коммерческое использование эти лицензии не позволяют |
| D3 | Только открытое ПО: Godot, Python, llama.cpp, stable-diffusion.cpp, SQLite | Требование автора |
| D4 | **Python** отвечает за ядро и логику, **Godot** только за отображение | Ядро можно тестировать без графики |
| D5 | Связь Godot ⇄ Python через WebSocket на localhost | Просто, переносимо, легко отлаживать |
| D6 | **ИИ не меняет мир напрямую**, а только предлагает действия, которые проверяет валидатор | Защита от галлюцинаций |
| D7 | Журнал событий только дополняется; откат делается через снимки | Перемотка времени и неизменная история |
| D8 | Мир пиксельный (LPC, вид сверху); портреты в диалоге аниме или пиксельные, на выбор | Быстрый прототип, единый стиль |
| D9 | В сцене диалога до 5 персонажей на переднем плане, остальные на заднем | Читаемость сцены |
| D10 | Мир и персонаж хранятся отдельно: любой герой подходит к любому сценарию | Открытые сценарии |
| D11 | Разработка начинается на **Linux Fedora** | Система автора |
| D12 | Порядок разработки: ядро → симуляция → ИИ → валидатор → память → графика | Сначала надёжная основа |

# Журнал решений

Каждое решение фиксируется здесь, чтобы не обсуждать его заново.
Чтобы отменить решение, нужно добавить новую запись, а не стирать старую.

| № | Решение | Почему |
|---|---|---|
| D1 | Название **Matricaria**, логотип: пиксельная ромашка | Латинское имя ромашки; *matrix* означает «источник» |
| D2 | Проект открытый и некоммерческий; код под **GPL-3.0** | Графика LPC требует совместимой лицензии; запретить чужое коммерческое использование эти лицензии не позволяют |
| D3 | Только открытое ПО: Godot, Python, llama.cpp, stable-diffusion.cpp, SQLite | Требование автора |
| D4 | **Python** отвечает за ядро и логику, **Godot** только за отображение | Ядро можно тестировать без графики |
| D5 | Связь Godot ⇄ Python через WebSocket на localhost | Просто, переносимо, легко отлаживать |
| D6 | **ИИ не меняет мир напрямую**, а только предлагает действия, которые проверяет валидатор | Защита от галлюцинаций |
| D7 | Журнал событий только дополняется; откат делается через снимки | Перемотка времени и неизменная история |
| D8 | Мир пиксельный (LPC, вид сверху); портреты в диалоге аниме или пиксельные, на выбор | Быстрый прототип, единый стиль |
| D9 | В сцене диалога до 5 персонажей на переднем плане, остальные на заднем | Читаемость сцены |
| D10 | Мир и персонаж хранятся отдельно: любой герой подходит к любому сценарию | Открытые сценарии |
| D11 | Разработка начинается на **Linux Fedora** | Система автора |
| D12 | Порядок разработки: ядро → симуляция → ИИ → валидатор → память → графика | Сначала надёжная основа |
| D13 | Перед ядром проводится **эксперимент по надёжности ИИ** (версия 0.2) | Проверить архитектуру на цифрах, пока её дёшево менять |
| D14 | Версии 0.1–1.0 по дорожной карте; сейчас **0.1 — планирование** | У каждой версии проверяемый результат |
| D15 | Один чат Claude Code = одна задача; работа в ветках через Pull Request; 1–2 чата одновременно | Чаты не помнят друг друга, нужен порядок |
| D16 | Память проекта хранится в репозитории: `CLAUDE.md`, decisions, roadmap, CHANGELOG | Любой новый чат сразу понимает проект |
| D17 | Критичное (предметы, деньги, здоровье, смерть, перемещения) проверяет **код**, а не ИИ | Валидатор-ИИ тоже может ошибаться |
| D18 | **Бой описательный с кубиками** внутри сцены диалога; проверки d20 по 5 характеристикам и в бою, и в разговоре; кубики бросает ядро | Просто, ролево, ИИ не решает исход |
| D19 | **Инвентарь — простой список** без веса и ячеек; торговля с ценами от экономики мира и отношения продавца | Достаточно для песочницы, легко проверять кодом |
| D20 | **Мультиплеер после 1.0**, но ядро сразу поддерживает несколько героев (`controller`, `actor_id`) | Не переделывать ядро потом |
| D21 | Для разработки и эксперимента — **OpenRouter**; поддерживаются любые OpenAI-совместимые сайты (NanoGPT и др.) и локальные модели (встроенный llama.cpp, Ollama, LM Studio) | Свобода выбора, один код для всех |
| D22 | Правила можно нарушать **явно**: способности персонажей (боги, магия), три режима правил (строгий / повествовательный по умолчанию / свободный), режим рассказчика. Изменения идут через ядро с основанием `rules` / `ability` / `author` | Свобода игрока без поломки мира; ИИ сам правила не нарушает |
| D23 | Главный критерий — **весело играть**; с версии 0.5 у каждой версии тест на веселье | Это игра, а не только технология |
| D24 | Эксперимент 0.2 идёт через **NanoGPT** (ключ есть у автора) вместо OpenRouter; остальное из D21 в силе | У автора уже есть ключ NanoGPT |
| D25 | **Бой — отдельный режим и экран** (заменяет «внутри сцены диалога» из D18; кубики и проверки из D18 в силе). Анимации: кубик, тряска, урон, рывок и ранение портретов, особый крит. Настройка **«Показывать кубики»**: если выключена, скрыты кубик, числа урона и полоски здоровья. Союзники, предметы окружения, кнопка «Начать драку». Огнестрельное оружие опаснее (пистолет 3–12, ружьё 4–16) и реже | Бой можно отдельно проработать и улучшать; анимации добавляют драмы; анимация только показывает результат ядра |
| D26 | **Мультиплеер не планируется** (заменяет D20). В ядре остаётся `actor_id` у событий (нужен журналу и без мультиплеера) и `controller` (игрок или ИИ); отдельные знания и отношения NPC к нескольким героям не готовим | Автор не планирует мультиплеер; ядро проще |
| D27 | **Фэнтези и современность равноправны.** У героя и NPC есть **профессия** (+2 к своим проверкам, зарплата, можно сменить). Новые места появляются по ходу игры: ИИ предлагает, ядро проверяет и записывает навсегда. Новый принцип: **«Можно стать кем угодно и делать что угодно»**. В современности вместо магии — таланты и технологии | Важно для автора; разные профессии — разные способы играть |
| D28 | **Пять шкал отношений:** симпатия, доверие, страх, уважение (−100…100), любовь (0…100); на отношение влияет профессия. В диалоге меняются эмоция и поза | Больше оттенков в отношениях, романтические линии |
| D29 | Список принципов в [01](01-vision.md) сокращён до «весело», «ИИ описывает», «локально», «без программирования» и нового из D27. Убранные из списка правила (придуманное остаётся, NPC знает только увиденное, открытое ПО, явное нарушение правил) **в силе**. Из «Чего не будет» убраны 3D-графика и онлайн-сервер | Решение автора при согласовании 01 |
| D30 | Тип сценария **«Уютная история»**: главные герои `{{user}}` и `{{char}}` (ИИ), сюжет любой по цели игрока, без боя и оружия, тёплые события, кубики по желанию; передвижение на выбор игрока — карта или режим сцен, как в визуальной новелле | Романтика, повседневная комедия, добрые истории; сильная сторона игры — память и отношения |
| D31 | **Импорт персонажей** в формате Character Card V2/V3 (SillyTavern, Chub, выгрузки Janitor AI): поля переносятся автоматически, недостающее предлагает ИИ, игрок подтверждает на экране «Проверьте персонажа». Скрытые описания не обходим; инструкции карточки не отменяют правил ядра. В 0.6 — через терминал, в 0.9 — перетаскиванием | Играть с уже любимыми персонажами в живом мире |

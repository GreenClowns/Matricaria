# 06. Форматы ИИ (черновик)

## Провайдеры

Все провайдеры работают через **один OpenAI-совместимый интерфейс** (`/v1/chat/completions`), поэтому код у них общий, а отличаются только адрес, ключ и название модели.

| Вид | Примеры | Для кого |
|---|---|---|
| **Агрегаторы API** | OpenRouter (основной для разработки), NanoGPT и похожие сайты | Один ключ — много моделей разных компаний |
| **Прямой API** | Сервисы отдельных компаний с OpenAI-совместимым адресом | Кому нужна конкретная модель |
| **Локально, встроенно** | `llama-server` (llama.cpp), запускается ядром само | Мощный компьютер, бесплатно, без интернета |
| **Локально, внешне** | Ollama, LM Studio, KoboldCpp или свой сервер в сети | Кто уже пользуется этими программами |

В настройках есть **готовые шаблоны** (адрес уже вписан, нужно только вставить ключ) и вариант **«Свой адрес»** для любого совместимого сайта.
Адреса шаблонов проверяются при реализации (версия 0.5) и записываются в настройки, а не в код.

Можно назначать разные модели для разных задач:
- **диалоги** — самая сильная доступная модель;
- **проверки и извлечение фактов** — дешёвая или локальная;
- **сводки и хроника** — средняя.

Ключи хранятся только на компьютере пользователя (в разработке — в файле `.env`, который не попадает в git).

### Различия провайдеров

Не все сервисы одинаково поддерживают строгий JSON-формат ответа. Поэтому:
1. если провайдер поддерживает JSON-схему — используем её;
2. если нет — просим JSON в инструкции, проверяем ответ и при ошибке повторяем запрос;
3. у локального llama.cpp — грамматика, которая гарантирует формат.

## Сборка запроса (в порядке приоритета)

1. Правила мира и стиль повествования.
2. Карточка говорящего NPC: личность, манера речи, текущая эмоция.
3. Его отношение к присутствующим и его **личная** память.
4. Сработавшие записи лорбука (в пределах бюджета токенов).
5. Хроника и сводки.
6. Последние 15–20 сообщений.
7. Сцена: где, когда, кто присутствует.
8. Инструкция: «Опирайся только на эти факты. Если не знаешь — персонаж говорит, что не знает».

## Формат ответа

Ответ ограничен JSON-схемой (в llama.cpp через грамматику), поэтому модель не может вернуть неверный формат.

```json
{
  "say": "Опять ты? Двадцать монет — и вперёд.",
  "emotion": "suspicious",
  "actions": [
    { "type": "relation_change", "target": "player", "trust": -5 }
  ],
  "facts": [
    { "subject": "location_tavern", "predicate": "room_price", "object": "20" }
  ]
}
```

- `emotion` — только из списка: `neutral`, `happy`, `angry`, `sad`, `surprised`, `embarrassed`, `suspicious`, `scared`.
- В `actions` и `facts` можно ссылаться только на существующие id. Их список подставляется в схему.

## Разрешённые действия (первая версия)

| type | Что делает |
|---|---|
| `relation_change` | Изменить отношение (не больше ±10 за реплику) |
| `give_item` / `take_item` | Передать предмет (только если он есть у отдающего) |
| `pay` | Передать деньги |
| `move_to` | NPC уходит в другую локацию |
| `remember` | NPC запоминает событие |
| `call` | Позвать персонажа в сцену |
| `check` | Запросить проверку (например, Обаяние против 12) — бросает ядро |
| `attack` | Атаковать — урон и попадание считает ядро |
| `trade` | Предложить сделку — цену считает ядро |
| `miracle` | Чудо (воскрешение, создание предмета…) — **только для персонажа со способностью** |

## Служебные задачи ИИ

Все с низкой температурой:
- **сводка:** сжать события в 3–5 строк, только по журналу;
- **извлечение фактов:** найти утверждения в реплике (для валидатора);
- **хроника:** пересказ журнала после пропуска времени.
